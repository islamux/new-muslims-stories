# New Muslim Stories Blueprint

## System Overview

This web application, built with Next.js and TypeScript, focuses on showcasing stories of new Muslims from around the world. The application aims to be a source of inspiration and an introduction to the experiences of these individuals and how they embraced Islam, along with brief information about their previous cultural and religious backgrounds. The goal is to convey powerful human and spiritual messages in a visually appealing and engaging manner.

The system is a statically rendered, bilingual (English/Arabic) App Router site. Markdown stories in `src/stories/` are validated, parsed, and sanitized by the content repository, then rendered by locale-aware pages. A service worker provides offline reading and PWA installation, while `next-intl` supplies routing, messages, and RTL layout.

## Local Interface & Invariants

- `package.json` scripts — `test` runs `vitest run`; `build` runs `next build`; `build:static` sets `STATIC_EXPORT=true` and copies the static-host `.htaccess` and `404.html`. `[package.json:scripts]`
- `next.config.mjs` — `withNextIntl` points at `./src/i18n/request.ts`. `[next.config.mjs:withNextIntl]`
- `next.config.mjs` — `CSP` and `securityHeaders` define the Content Security Policy and response headers. `[next.config.mjs:CSP]` `[next.config.mjs:securityHeaders]`
- `next.config.mjs` — `isStaticExport` is true only when `STATIC_EXPORT === 'true'`. `[next.config.mjs:isStaticExport]`
- `next.config.mjs` — image formats are AVIF and WebP with the declared device/image sizes. `[next.config.mjs:images]`
- `vitest.config.ts` — jsdom environment, global test APIs, `./src/test/setup.ts`, and `src/**/*.test.{ts,tsx}`. `[vitest.config.ts:test]`
- `vitest.config.ts` — the `@` alias resolves to `./src`. `[vitest.config.ts:resolve]`
- `eslint.config.mjs` — ignores `.next/**`, `out/**`, `build/**`, `next-env.d.ts`, `public/sw.js`, and `scripts/**`. `[eslint.config.mjs:ignores]`
- `postcss.config.mjs` — Tailwind CSS and Autoprefixer plugins. `[postcss.config.mjs:config]`
- `next-env.d.ts` — generated by Next.js; the file states it should not be edited. `[next-env.d.ts:NOTE]`

Local invariants:

- Static export mode sets `output: 'export'`, `trailingSlash: true`, and disables image optimization; non-static mode adds the security headers to every route. `[next.config.mjs:isStaticExport]` `[next.config.mjs:securityHeaders]`
- The repository verification command is `pnpm test` (`vitest run`). `[package.json:scripts]`

## Subdirectories & System Boundaries

- `public`: [`./public/README.md`](./public/README.md) — static assets, PWA manifest/icons, and the service worker.
- `scripts`: [`./scripts/README.md`](./scripts/README.md) — content auditing, image optimization, icon generation, documentation index regeneration, and image-reference migration.
- `src`: [`./src/README.md`](./src/README.md) — App Router pages, React components, hooks, i18n configuration, core library, and TypeScript contracts.
- Non-contract directories: `docs/` (project documentation), `messages/` (translation JSON), and `presentation-en/` (presentation assets). These contain no application source contracts.

## Global Invariants

- Supported locales are exactly `en` and `ar`, with `en` as the default. `[src/i18n/routing.ts:routing]`
- Locale layouts and pages call `setRequestLocale(locale)` before using `next-intl` data. `[src/app/[locale]/layout.tsx:LocaleLayout]` `[src/app/[locale]/page.tsx:Home]`
- Story frontmatter is validated by a zod `strictObject`; invalid or unknown fields fail the build. `[src/lib/content/schema.ts:storyFrontmatterSchema]`
- The story detail route sets `dynamicParams = false`, so only slugs returned by the repository are renderable. `[src/app/[locale]/stories/[slug]/page.tsx:dynamicParams]`
- Security headers and the Content Security Policy apply to all routes in non-static builds. `[next.config.mjs:securityHeaders]`

## Global Side Effects

- The story repository reads Markdown files from `src/stories` on the filesystem. `[src/lib/content/index.ts:storyRepository]`
- The service worker precaches routes, intercepts fetches, and manages Cache Storage. `[public/sw.js:PRECACHE_URLS]`
- Plausible Analytics injects its script and sends pageview events when a domain is configured. `[src/components/PlausibleAnalytics.tsx:loadPlausibleScript]`
- The client persists the active locale and PWA dismissal state in `localStorage`. `[src/components/LocalePersist.tsx:LocalePersist]` `[src/components/PWAInstall.tsx:PWAInstall]`
- Maintenance scripts write documentation reports, generated indexes, icons, optimized images, and story Markdown. `[scripts/audit-ar-stories.mjs:REPORT_OUT]` `[scripts/regenerate-doc-indexes.mjs:writeIfChanged]`

*   **Overall Aesthetic:** Attractive and modern interface with calm and spiritual touches.
*   **Homepage:**
    *   Elegant header with a welcoming phrase (e.g., "Stories of Guidance from Around the World").
    *   Featured Stories section displaying selected stories using animated cards.
    *   "Who are New Muslims?" section with introductory information.
*   **Individual Story Page:**
    *   Person's photo (if available), country, first name only (for privacy), and age.
    *   Brief background about their life before Islam.
    *   Details about the moment of conversion and reason for embracing Islam.
    *   Impactful quotes from them after embracing Islam.
*   **Visual Effects:**
    *   Scroll-triggered animations.
    *   Calm color gradients (colors like light green, beige, gold, sky blue).

## Internationalization (i18n)

This project supports English and Arabic with full RTL support using `next-intl`.

### Key i18n Files

- **`src/i18n/routing.ts`** - Central routing configuration
- **`src/i18n/request.ts`** - Request configuration for Next.js 16
- **`src/proxy.ts`** - Middleware for locale routing
- **`messages/en.json`** - English translations
- **`messages/ar.json`** - Arabic translations

### Important: Next.js 16 + next-intl Setup

**This project uses Next.js 16 which requires specific i18n setup:**

1. **`setRequestLocale()` must be called** in all layouts and pages before using `getMessages()` or `useTranslations()`

2. **File naming changes:**
   - `middleware.ts` → `proxy.ts` (Next.js 16 rename)
   - `i18n.ts` → `i18n/request.ts` (new API)

3. **Centralized routing config:**
   - All locale config is in `src/i18n/routing.ts`
   - Imported by `proxy.ts`, `navigation.ts`, and `request.ts`

### Adding New Translations

1. Add keys to both `messages/en.json` and `messages/ar.json`
2. Use in components: `const t = useTranslations('Namespace'); t('key')`

### Common Issues

**Arabic pages showing English?**
- Ensure `setRequestLocale(locale)` is called in `src/app/[locale]/layout.tsx`
- Check that `proxy.ts` excludes static assets: `matcher: ['/((?!api|_next|.*\\..*).*)']`

For detailed troubleshooting, see [`docs/NEXT_INTL_FIX_GUIDE.md`](docs/NEXT_INTL_FIX_GUIDE.md).
