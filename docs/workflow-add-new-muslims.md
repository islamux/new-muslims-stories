# Workflow: Adding New Muslim Stories (repeatable batch process)

> This is the standing playbook for adding new Muslims to `src/stories/`. Every time you
> (agent or human) start a batch, follow it top to bottom. **This file — not memory — is
> the process.** After each batch ends, do not edit this file unless the process itself
> changes (that is a separate, deliberate change).

## Step 0 — Read the current state first (never skip)

1. Read `docs/existing-muslims.md` (the index: slug, EN/AR names, country, previous religion).
2. Read `docs/muslim-names.md` (the names-only roster).
3. Count sanity: every story is an EN + `-ar` pair. One *naming* exception: `joram-van-klaveren.md`
   has no `-story` suffix (its AR pair `joram-van-klaveren-ar.md` exists) — neither file is matched
   by the `ls` globs below, which therefore show 98/98 plus the joram pair = 99 stories.
   `ls src/stories/*-story.md | wc -l` must equal `ls src/stories/*-story-ar.md | wc -l`.

## Step 1 — Candidate shortlist + duplicate check (no writing yet)

Build a comparison table for every candidate and present it to the owner BEFORE writing
any story:

| Candidate | Country | Previous religion | Sources (URLs) | Public photo? | Verdict vs existing 99 |

Duplicate rule (**match by name AND country**): a candidate who shares the name with an
existing Muslim but differs by country may still be the same person — verify via sources.
Current contents live in the index (`docs/existing-muslims.md`), so search it first.

## Step 2 — Verify every identity via the web

- Each candidate needs at least one trustworthy source (news, official site, interview,
  video) pinning: who they are, when/what they converted from, their Muslim name if any.
- **Unverifiable public identity → drop the candidate.** Precedent: Batch 2 dropped
  `jerome-correia-story` for exactly this. Log the drop + reason in the batch todo file.

## Step 3 — Write story pairs (never singles)

For each accepted candidate, create jersey files in `src/stories/`:

- `{slug}.md` (English) and `{slug}-ar.md` (Arabic), both with frontmatter matching
  `src/lib/content/schema.ts` exactly:
  `title`, `author`, `language`, `date`, `firstName` (optional), `image`/`profilePhoto`
  (optional), `age` (optional), `country`, `previousReligion`, `featured` (optional).
  Unknown/misspelled fields FAIL `pnpm build` (zod strict).
- Body structure mirrors an existing story (`## My Life Before Islam`, `## The Moment
  of Guidance`, …) — read one recent story before writing.
- Arabic file is a real translation, not a copy: follow the standards in
  `docs/ar-translation-audit.md` (no Latin/Cyrillic contamination inside Arabic text).

## Step 4 — Images only when a public photo exists

- If no verifiable public photo: omit `image` and `profilePhoto` entirely (parser-safe;
  Batch 2 shipped 5 such stories).
- If a photo exists: add to `public/images/stories/` as WebP, then run
  `node scripts/optimize-images.mjs` + `node scripts/update-image-refs.mjs` so frontmatter
  references stay normalized.

## Step 5 — Pilot first, approval, then the batch

Write 2–3 pilot stories → owner reviews/approves style and tone → then write the rest of
the batch in the same session or follow-ups. Never write 25 stories before a pilot is
approved.

## Step 6 — Regenerate the reference docs (the anti-forgetting step)

```
node scripts/regenerate-doc-indexes.mjs
```

- Updates `docs/existing-muslims.md` (table) and `docs/muslim-names.md` (names list).
- **These are generated files — never hand-edit them.** The script leaves them
  byte-identical if nothing changed (verify: `git diff` after running).
- Commit the two files together with the story files.
- Sanity after regen: `_Total Muslims: N_` matches the new count; no rows dropped
  (`git diff docs/existing-muslims.md` shows additions only).

## Step 7 — Gates (order matters)

1. `pnpm lint` — clean.
2. `pnpm test` (vitest) — full suite green, including the regen byte-equality tests.
3. `pnpm build` — zod validation passes for every new file; route count grows by
   2 per added pair.

## Step 8 — GitHub Flow

Fresh branch (lowercase kebab-case, e.g. `content-batch3-stories`) → commit(s) →
`git push -u origin <branch>` → `gh pr create` → owner reviews/merges (never delete the
branch, per repo policy).

## Step 9 — Batch bookkeeping (do not skip)

- New batches get their own `todo-batch-N.md` at the repo root (Batch 2 = `todo.md`,
  done). Copy the checked/unchecked structure from `todo.md`.
- `todo.md` and `todo2.md` are **historical records — never delete them**.
- The final batch todo item is always the last unchecked box: run the finish-work flow
  (gates in order, owner confirmation BEFORE merge) and only check it off when shipped.

## Quality bars (the bar never drops, even "for one story")

1. Identity verifiable in public sources or the candidate is dropped.
2. No duplicates by name AND country.
3. EN + AR pair for every story, both schema-valid.
4. No hand-edits to the generated docs.
5. Owner approval after the pilot, before the wave.
6. Gates green before any PR is opened.
