# حزمة العرض التقديمي — presentation/

هذه الحزمة مخصّصة للعرض التقني لمدّة ٦٠ دقيقة عن مشروع **New Muslim Stories** (Next.js 16 · bilingual en/ar · SSG). تحتوي على أربعة ملفات تفصّلها الأقسام أدناه. اللغة الساردة هنا عربية مع مصطلحات تقنية إنجليزية، تماشياً مع بقية الحزمة.

---

## ١) مكوّنات الحزمة — أدوار كل ملف

| الملف | المسؤولية |
|---|---|
| `README.md` | هذا الملف — دليل التشغيل للعرض من الصفر: ما كل ملف، ترتيب الاستخدام، كيف تُفتح الشرائح، الاختصارات الحقيقية، شروط البيئة، وقائمة التحضير. |
| `slides.html` | الشريحة التقديمية ذاتية الاحتواء (self-contained deck) — ٣٢ شريحة تُفتح في المتصفح مباشرة بلا build ولا server. فيها كل محتوى العرض: الأطروحة، رحلة القرارات، النموذج الذهني، الغوص التقني، العرض الحيّ، المقايضات، الخارطة الطريق. |
| `demo-script.md` | سكربت العرض الحي (live demo) خطوة بخطوة — مدة كاملة ~11 دقيقة مع خطة بديلة ~6 دقائق. يعتمد على **production build** (انظر قسم شروط البيئة). |
| `qa-guide.md` | دليل فريق Q&A — ٣١ سؤالاً متوقّعاً مع إجابات مقترحة، للاستعداد لجلسة الأسئلة. |

---

## ٢) ترتيب الاستخدام

1. **اقرأ `README.md`** — افهم بنية الحزمة وشروطها أولاً.
2. **افتح `slides.html`** في المتصفح وتصفّحها لفهم سرد العرض.
3. **تدرّب على `demo-script.md`** — شغّل العرض الحي أكثر من مرة مع المؤقّت.
4. **استعدّ للأسئلة بـ `qa-guide.md`** — راجع الإجابات المقترحة وطابقها مع الشريحة المعنية.

---

## ٣) فتح/تشغيل الشرائح

`slides.html` ملف **self-contained**: كل الأنماط (CSS) والسكربت (JS) مضمّنة فيه، وخطوطه من النظام (system font stack). لذلك:

- افتحه مباشرة في أي متصفح حديث (سحب وإفلات أو `file://`).
- **لا يتطلب build ولا server** — يعمل في وضع offline ذاتياً.
- يمكن تصديره للطباعة/PDF عبر قائمة المتصفح (له `@media print` مُجبّرة في المصدر) — مفيد للنسخ الاحتياطي.

---

## ٤) اختصارات لوحة المفاتيح والتحكم — كما في المصدر تماماً

مأخوذة حرفياً من `slides.html` (معالج `keydown` في سكربت المصدر):

| المفتاح | الوظيفة |
|---|---|
| `→` `ArrowRight` | الانتقال للشريحة التالية |
| `←` `ArrowLeft` | الانتقال للشريحة السابقة |
| `N` / `n` | فتح/إغلاق لوحة ملاحظات المتحدث (Speaker Notes) |
| `F` / `f` | تبديل وضع ملء الشاشة (fullscreen) |
| `A` / `a` | فتح/إغلاق نظرة عامة على كل الشرائح (overview) |
| `Escape` | إغلاق النظرة العامة إذا كانت مفتوحة؛ وإلا إغلاق لوحة الملاحظات إذا كانت مفتوحة |

**عناصر التحكم المباشرة** (شريط أسفل الشاشة):
- زر «السابق» (`#prevBtn`, aria-label «الشريحة السابقة») بجانب زر «التالي» (`#nextBtn`, aria-label «الشريحة التالية»).
- عدّاد «xx / 32» (`#count`) — يُحسب ديناميكياً من عدد `.slide` في DOM.
- زر ملء الشاشة (`#fullscreenBtn`, aria-label «تبديل وضع ملء الشاشة»).
- تلميح داخل الشريط: «أزرار: ← → للتنقل · N ملاحظات · F ملء الشاشة · A نظرة عامة».
- أزرار إغلاق: «إغلاق (A)» للنظرة العامة (aria-label «إغلاق النظرة العامة»)، و«×» للملاحظات (aria-label «إغلاق الملاحظات»).

**اللمس (touch):** سحب أفقي (swipe) للتنقل، بعتبة 50px. ولأن الصفحة `dir="rtl"` (المصدر `<html lang="ar" dir="rtl">`)، تنعكس الاتجاهات: السحب لليمين → التالي، والسحب لليسار → السابق (المصدر يطابق منطق RTL).

## ٥) شروط البيئة الحقيقية (صريحة)

- **عرض PWA / offline الحي يتطلب production build.** تسجيل الـ Service Worker (`ServiceWorkerRegistration.tsx`) لا يُقيَّد بـ env ظرفي، لكن `/sw.js` لا يوفّر تجربة offline/PWA موثوقة إلا من بناء إنتاجي. لذلك لتجربة offline/التثبيت يجب أولاً:
  ```
  pnpm install
  pnpm build
  pnpm start
  ```
  مع تنبيه: `pnpm start` يتطلب بناءً سابقاً، و`node_modules` موجوداً.
- **الخطوط:** مستندة للنظام (system stack) — فلا حاجة لشبكة لتحميل الخطوط.
- **اختبارات/أدوات موجودة فعلاً** في `package.json`: `pnpm dev`، `pnpm build`، `pnpm start`، `pnpm test` (= `vitest run`، 5 ملفات / 29 اختباراً)، `pnpm lint`، `pnpm format`، `pnpm format:check`.
- كل أمر مذكور أعلاه موجود في `package.json` — لا شيء مخترَع.

## ٦) قائمة التحضير قبل العرض (٦٠ دقيقة)

### أ) تشغيل كامل مقابل جدول الزمن
شغّل الشرائح كاملة مرة واحدة مع مؤقّت، وقارنها بجدول التوزيع الزمني (يجب أن **يُجمع إلى ٦٠**):

| القسم | الشرائح | الدقائق |
|---|---|---|
| Opening | 1-4 | ٥ |
| Thesis | 5-6 | ٤ |
| Decisions | 7-10 | ٧ |
| Mental model | 11 | ٤ |
| Product | 12-14 | ٥ |
| Deep dive | 15-27 | ١٤ |
| Demo | 28 | ١١ |
| Trade-offs | 29-30 | ٤ |
| Roadmap | 31 | ٣ |
| Closing | 32 | ٣ |
| **المجموع** | — | **٦٠** |

### ب) تحقّق من عدد الشرائح والفهرسة
- تأكد أن العدّاد يعرض «xx / 32» — فالمصدر يحسب `total` ديناميكياً من عدد `.slide` (32 فعلاً في الملف).

### ج) أوامر ما قبل العرض (preflight)
شغّل وثبّت أنها تمر قبل الصعود للمسرح:
- `pnpm install`
- `pnpm test` (5 ملفات / 29 اختباراً)
- `pnpm lint`
- `pnpm dev`

### د) خطة demo البديلة
- إن لم يتوفر production build أو البيئة مناسبة، جهّز خطة مختصرة (السكربت القصير ~6 دقائق في `demo-script.md`) أو اعتمد على لقطات شاشة ثابتة للواجهة.

### هـ) اختبار الشرائح نفسها في المتصفح
افتح `slides.html` وذاتك من:
- التنقل بلوحة المفاتيح (←/→)،
- ملء الشاشة (F)،
- لوحة الملاحظات (N)،
- النظرة العامة (A) والقفز عبر الشرائح،
- دعم اللمس (إن عُرض على جهاز لمس).

### و) العرض على جهاز العرض (projector) والطباعة
- تحقق من تصدير الطابعة/PDF وأن الشرائح تُعرض سليمة على جهاز العرض: **aspect ratio**، عدم قصّ النصوص، ووضوح كل شريحة.

### ز) نسخة احتياطية للـ demo
- جهّز نسخة احتياطية (لقطات شاشة أو build ثابت) لأن العرض الحي قد يكون هشّاً (يعتمد على `pnpm build` + `pnpm start`).
